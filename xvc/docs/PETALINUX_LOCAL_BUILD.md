## 1. Background: why it goes online by default

Yocto's `do_fetch` task performs the following for each recipe:

```
① Check whether DL_DIR already holds the source
② If it does: verify integrity
     - tarball → download the .md5 / .sha256 checksum files
     - git     → run git ls-remote to confirm the commit exists
③ If it does not: download from SRC_URI
```

**Step ② is exactly why "every build goes online"**. Even with 17 GB of sources already local,
Yocto still contacts upstream to confirm nothing changed. Consequences:

- Slow network → the build stalls in `do_fetch`
- Upstream deleted the tag/commit → the build fails outright
- Air-gapped environment → cannot build at all

### Approach

Register the local `DL_DIR` as a **PREMIRROR** (a preferred mirror source) and forbid network fallback:

```
fetch request → PREMIRROR(file://DL_DIR) → hit ✓ → no upstream access
                                     ↘ miss → error (BB_NO_NETWORK=1)
```

## 2. Cache directory structure

The `build/` directory of a PetaLinux project:

```
build/
├── conf/
│   ├── local.conf          ← the config we are going to change
│   ├── plnxtool.conf       ← generated by PetaLinux, do not edit
│   └── petalinuxbsp.conf   ← same as above
├── downloads/              ← ★ source cache (the core of this manual)
│   ├── acl-2.3.1.tar.gz
│   ├── acl-2.3.1.tar.gz.done     ← completion marker
│   ├── ...
│   └── git2/                     ← git bare repositories
│       ├── github.com.Xilinx.u-boot-xlnx.git/
│       └── ...
├── sstate-cache/           ← shared state cache (build artifacts)
└── cache/                  ← bitbake internal cache
```

### Measured size on this machine

| Directory | Size | Contents |
|---|---|---|
| `build/downloads` | **17 GB** | 470 archives + 169 git repositories |
| `build/sstate-cache` | **3.1 GB** | Build artifact cache |

## 3. One-time configuration

### 3.1 Edit `build/conf/local.conf`

Append the following to the **end** of the file:

```conf
# ============================================================
# Offline build: use local source packages
# ============================================================

# Register DL_DIR as a PREMIRROR
INHERIT += "own-mirrors"
SOURCE_MIRROR_URL = "file://${DL_DIR}"
BB_GENERATE_MIRROR_TARBALLS = "1"

# Forbid the network: a missing package errors immediately instead of silently re-downloading
BB_NO_NETWORK = "1"
BB_FETCH_PREMIRRORONLY = "1"

# Shared sstate (optional, reuses build artifacts across projects)
SSTATE_DIR ?= "${TOPDIR}/../sstate-cache-shared"
```

### 3.2 Variable descriptions

| Variable | Effect | Required |
|---|---|---|
| `INHERIT += "own-mirrors"` | Enables the local mirror class | ✅ |
| `SOURCE_MIRROR_URL` | Points at `DL_DIR` | ✅ |
| `BB_GENERATE_MIRROR_TARBALLS` | Generates tarballs from git repositories for easier mirroring | Recommended |
| `BB_NO_NETWORK` | Disables the network entirely | ✅ offline |
| `BB_FETCH_PREMIRRORONLY` | Fetches only from PREMIRROR | ✅ offline |
| `SSTATE_DIR` | Shared build cache | Optional |

### 3.3 Backup

```bash
cp build/conf/local.conf build/conf/local.conf.bak.$(date +%Y%m%d-%H%M)
```

## 4. Verifying offline operation

```bash
# Load the PetaLinux environment (required in every new shell)
source /opt/Xilinx/petalinux/2023.1/settings.sh
cd ~/work/xvc2

# ① Test a tarball-style recipe
petalinux-build -c zlib -x do_fetch

# ② Test a git-style recipe
petalinux-build -c u-boot-xlnx -x do_fetch
```

### Expected output

```
NOTE: recipe zlib-1.2.13-r0: task do_fetch: Succeeded        ✓
NOTE: recipe u-boot-xlnx-...-r0: task do_fetch: Succeeded    ✓
```

**Succeeding under `BB_NO_NETWORK=1` = fully offline** ✓

### If it fails

```
ERROR: ... do_fetch: Fetcher failure: Unable to find file ...
```

→ That package is not in the cache. Temporarily comment out `BB_NO_NETWORK` and `BB_FETCH_PREMIRRORONLY`,
let it download once, then restore them after it succeeds.

## 5. Complete offline build flow

```bash
# ===== Step 1: environment =====
source /opt/Xilinx/petalinux/2023.1/settings.sh
cd ~/work/xvc2

# ===== Step 2: clear leftovers from the last run (optional, mandatory when a build hangs)=====
pkill -9 -f bitbake 2>/dev/null
rm -rf build/bitbake.lock build/bitbake.sock \
       build/cache/prserv.sqlite3* 2>/dev/null

# ===== Step 3: build =====
petalinux-build

# ===== Step 4: package BOOT.BIN =====
petalinux-package --boot \
  --fsbl  images/linux/zynq_fsbl.elf \
  --fpga  images/linux/system.bit \
  --u-boot images/linux/u-boot.elf \
  --force

# ===== Step 5: confirm the artifacts =====
ls -l images/linux/BOOT.BIN images/linux/image.ub
md5sum images/linux/BOOT.BIN images/linux/image.ub
```

### Time reference (this machine)

| Stage | Time |
|---|---|
| Full build (first time, with sstate) | ~45 minutes |
| Full build (subsequent, sstate hits) | ~10 minutes |
| Application code change only | ~3 minutes |
| `do_fetch` for a single recipe | 2-5 seconds |

## 6. Reusing the cache in a new project

`DL_DIR` defaults to `${TOPDIR}/downloads` (per project). To reuse the 17 GB cache in a new project,
**use hard links**: no extra space, and it takes < 5 seconds:

```bash
# 1. Create a new project
petalinux-create -t project -n xvc3 --template zynq
cd xvc3

# 2. Hard-link the download cache (requires the same partition)
cp -al ~/work/xvc2/build/downloads ./build/downloads

# 3. Hard-link sstate
cp -al ~/work/xvc2/build/sstate-cache ./build/sstate-cache

# 4. Copy the offline configuration
cat >> build/conf/local.conf <<'CONF'
INHERIT += "own-mirrors"
SOURCE_MIRROR_URL = "file://${DL_DIR}"
BB_GENERATE_MIRROR_TARBALLS = "1"
BB_NO_NETWORK = "1"
BB_FETCH_PREMIRRORONLY = "1"
CONF

# 5. Verify
source /opt/Xilinx/petalinux/2023.1/settings.sh
petalinux-build -c zlib -x do_fetch
```

### Why `cp -al` instead of `cp -r`

| Approach | Time for 17 GB | Extra disk |
|---|---|---|
| `cp -r` | ~2 minutes | 17 GB |
| **`cp -al`** | **< 5 seconds** | **0** |

`-a` preserves attributes, `-l` creates hard links (the same inode, two paths).

**Note**: the source and destination must be on the **same filesystem**. It does not work when `/home` and `/media` are on different partitions.

## 7. Team-shared cache (recommended)

With multiple people and/or multiple projects, keep all caches in one **shared location**:

### 7.1 Directory layout

```
/opt/yocto-shared/
├── downloads/        17 GB   source packages
├── sstate-cache/     3.1 GB  build cache
└── README.txt
```

### 7.2 Configure it centrally in `build/conf/site.conf`

`site.conf` is loaded automatically by **every** project (`local.conf` is per project):

```conf
DL_DIR = "/opt/yocto-shared/downloads"
SSTATE_DIR = "/opt/yocto-shared/sstate-cache"

INHERIT += "own-mirrors"
SOURCE_MIRROR_URL = "file:///opt/yocto-shared/downloads"
BB_GENERATE_MIRROR_TARBALLS = "1"

BB_NO_NETWORK = "1"
BB_FETCH_PREMIRRORONLY = "1"
```

### 7.3 Populating the shared cache for the first time

```bash
# On a machine with network access
mkdir -p /opt/yocto-shared/{downloads,sstate-cache}
# Temporarily comment out BB_NO_NETWORK and run one full build
# The cache fills automatically after the build; then restore the configuration
```

### 7.4 Permissions

```bash
sudo chown -R $USER:$USER /opt/yocto-shared
chmod -R u+rwX /opt/yocto-shared
```

## 8. Adding/upgrading a recipe

### 8.1 Adding a local application (no cache needed)

Our own applications live under `project-spec/meta-user/recipes-apps/`, with `SRC_URI` pointing at local files:

```bitbake
SRC_URI = "file://xvcserver_g1.c"
S = "${WORKDIR}"
```

**Such recipes do not trigger the network**; `file://` reads directly from the local machine.

### 8.2 Adding a third-party package (needs the network once)

```bash
# ① Temporarily allow the network
sed -i 's/^BB_NO_NETWORK = "1"/BB_NO_NETWORK = "0"/' build/conf/local.conf
sed -i 's/^BB_FETCH_PREMIRRORONLY = "1"/BB_FETCH_PREMIRRORONLY = "0"/' build/conf/local.conf

# ② Fetch only, do not compile
petalinux-build -c <recipe-name> -x do_fetch

# ③ Restore offline mode
sed -i 's/^BB_NO_NETWORK = "0"/BB_NO_NETWORK = "1"/' build/conf/local.conf
sed -i 's/^BB_FETCH_PREMIRRORONLY = "0"/BB_FETCH_PREMIRRORONLY = "1"/' build/conf/local.conf
```

New packages land in `build/downloads/` automatically and are then usable offline permanently.

### 8.3 Known issue: upstream branch renamed

For example, `cracklib` changed from `master` to `main`, so `do_fetch` fails. Fix:

```bitbake
# project-spec/meta-user/recipes-*/cracklib/cracklib_%.bbappend
SRC_URI = "git://github.com/cracklib/cracklib;branch=main;protocol=https"
```

## 9. Troubleshooting

### 9.1 `Unable to connect to bitbake server`

**Cause**: the previous build exited abnormally and left stale lock files.

```bash
pkill -9 -f bitbake
rm -rf build/bitbake.lock build/bitbake.sock \
       build/cache/prserv.sqlite3*
```

### 9.2 `Fetcher failure: Unable to find file ...`

**Cause**: the package is not in the cache.

```bash
# Check whether it is in the cache
ls build/downloads | grep <package-name>

# Not there → temporarily enable the network and download once (see 8.2)
```

### 9.3 `Error, TMPDIR has changed location`

**Cause**: the project directory was moved, so the absolute paths inside `TMPDIR` are no longer valid.

```bash
rm -rf build/tmp build/sstate-cache build/cache
petalinux-build    # full rebuild
```

### 9.4 `No checksum found`

**Cause**: a new package lacks a checksum.

```bash
# Temporarily enable the network so it downloads and generates a checksum
# After downloading, find the generated .bbappend under build/conf/ or use the SHA256 given in the error
```

### 9.5 The build hangs in `do_fetch` for a long time

**Diagnosis**:

```bash
# See which package it is
ps aux | grep -E "git|wget|curl" | grep -v grep

# Look at the cache completion markers
ls -la build/downloads/*.done | tail -5
```

**If it hangs even with `BB_NO_NETWORK=1`** → the configuration did not take effect; check:

```bash
bitbake -e <recipe> | grep -E "^BB_NO_NETWORK|^SOURCE_MIRROR_URL|^DL_DIR"
```

## 10. Appendix: full configuration file

### 10.1 This project's configuration in `build/conf/local.conf`

```conf
# ... the default PetaLinux content above ...

# Offline build configuration (2026-11-03)
INHERIT += "own-mirrors"
SOURCE_MIRROR_URL = "file://${DL_DIR}"
```

### 10.2 Key built-in variables (set automatically by PetaLinux)

```conf
TMPDIR   = "${TOPDIR}/tmp"
DL_DIR   = "${TOPDIR}/downloads"
INHERIT += "rm_work"          # delete the work directory after building to save space
INHERIT += "uninative"        # use prebuilt tools
```

### 10.3 Environment variables

```bash
# Must be loaded in every new shell
source /opt/Xilinx/petalinux/2023.1/settings.sh
```

### 10.4 Quick command reference

```bash
# Full build
petalinux-build

# Build only one recipe
petalinux-build -c <name>

# Run only fetch
petalinux-build -c <name> -x do_fetch

# Clean a recipe
petalinux-build -c <name> -x cleansstate

# Package BOOT.BIN
petalinux-package --boot --fsbl images/linux/zynq_fsbl.elf \
  --fpga images/linux/system.bit --u-boot images/linux/u-boot.elf --force

# Incremental application update (fastest)
petalinux-build -c <app-name> -x build
petalinux-build -c rootfs
petalinux-build -c image
```

## 11. Before vs. after

| Scenario | Before | After |
|---|---|---|
| `do_fetch` network access | ✅ every time | ❌ **never** |
| Upstream repository changes | ❌ build fails | ✅ unaffected |
| Offline build | ❌ fails | ✅ **succeeds** |
| First build | network needed | network needed (one time) |
| Subsequent builds | network needed | **fully offline** |
