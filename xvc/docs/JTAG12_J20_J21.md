# Mapping of 12 JTAG Signal Groups → J20 / J21 Expansion Connectors

> Based on "AX7Z020B Development Board User Manual V1.0" §2.17 Expansion Connectors (Tables 2.17.1 / 2.17.2).
> Each group carries 4 signals: **TCK / TMS / TDI / TDO** (no TRST, per user request).
> 12 groups = 48 signals; J20 carries 6 groups (pins 3–26), J21 carries 6 groups (pins 3–26).
> Both expansion connectors are **3.3 V LVCMOS** (the VCCO of BANK34/35 is set by a baseboard jumper, 3.3 V by default).

**Status**: `rtl/jtag12_io.v` + `constraints/jtag12.xdc` have been synthesized with Vivado 2022.2;
all 48 `PACKAGE_PIN`s are legal, all land in BANK34/35, `IOSTANDARD=LVCMOS33`, no conflicts
(IO report in [jtag12_io_report.rpt](jtag12_io_report.rpt)).

## Port Assignment

| Port | Meaning |
|---|---|
| **2542** | **Broadcast**: one TCK/TMS/TDI stream is delivered to all channels at once (requires PL-side multicast + TDO merge, see design doc §5.3) |
| **2543** | Channel 0 (read as G1 by humans) |
| 2544 | Channel 1 (G2) |
| … | … |
| **2554** | Channel 11 (G12) |

- Formula: **channel index = port − 2543**; human-readable channel number = port − 2542.
- 13 ports in total (1 broadcast + 12 channels).
- `xvcserver -b`: binds only 2542 (pure broadcast, does not open the channel ports).
- Current state: the hardware has only 1 TAP engine, so 2543 works, while 2544–2554 accept the
  connection and then close it immediately, printing `channel N has no TAP engine yet`; until
  hardware multicast is ready, the broadcast port is equivalent to channel 0.

## Default Levels With No Target Attached

J20/J21 currently **have no target attached**; to avoid floating inputs and an indeterminate
TAP state on the target side, weak pulls were added in the XDC:

| Signal | Weak Pull | Reason |
|---|---|---|
| TMS / TDI | PULLUP | Keeps the TAP in a defined state |
| TCK | PULLDOWN | Stays low when undriven |
| TDO | PULLUP | Floating input, avoids noise |

Once a target is attached these weak pulls do not affect normal operation. Note: **only channel 0
(2543) is connected to the Debug Bridge inside the PL**; the TCK/TMS/TDI of the remaining channels
are driven by placeholder logic for oscilloscope observation and cannot scan a target.

## Measurement: G1 with an External AMD Xilinx FPGA

On the board, J20 G1 was scanned with `jtagscan` (AXI GPIO bit-banging):

```
axi_gpio @ 0x41200000  DATA=0x0 TRI=0xFFFFFFFF  TDO=1
self-test: DATA(write 0x5) -> 0x5 OK
IDCODE = 0x0362C093
```

- `0x0362C093`: version 0, part `0x362C`, vendor `0x049` (Xilinx), LSB=1, Kintex-7 family (the specific part used for this measurement);
- This confirms that the four TCK/TMS/TDI/TDO wires are wired correctly and in the right direction (TDO is an input);
- Tool: `xvc/tools/jtagscan.c`, on the board `/usr/bin/jtagscan [-a 0x41200000] [-d ns]`.

G1 is implemented differently from the other 11 groups: G1 is driven by **AXI GPIO** bit-banging
(software controllable), while G2–G12 are still placeholder logic.

## Hardware TAP Engine (G1) Progress

| Item | Status |
|---|---|
| AXI-Lite slave (single-driver rewrite) | ✅ write/read-back self-test OK (`AXI self-test OK`) |
| Shift engine (LOAD/HIGH/LOW three-phase) | ✅ starts, busy handshake normal, shift completes on time |
| IDCODE read back | ❌ `0xFF800000` (should be `0x0362C093`), needs waveform capture to localize |
| Software bit-bang approach (previous generation) | ✅ `0x0362C093` verified; usable as a reference baseline |

Ruled out: AXI interface not connected (it is connected to `ps7_0_axi_periph_M01_AXI`),
multiple-driver registers (rewritten), busy handshake race (changed to "wait for busy to rise,
then wait for busy to fall"), pin mapping (R14/P14/U12/T12 and their directions are correct
in `impl_1`).

Next step: attach the system ILA probes to `tck/tms/tdi/tdo` (or add a second ILA), capture one
44-bit sequence, compare it against the software bit-bang timing, and determine whether this is
a sampling-phase issue or a target-response issue.
